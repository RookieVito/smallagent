# V0 边界

V0 只定义并实现智能旅行助手的最小可运行闭环，不追求完整产品形态。

一句话定义：

`V0 = 前后端完整闭环 + 生成 + 展示 + 基础编辑`

## V0 必须包含

- 用户可以提交一次结构化旅行请求。
- 后端可以基于既定工作流生成 `TripPlan`。
- 前端可以展示行程概览、预算、地图、每日行程和天气摘要。
- 用户可以对单日景点做删除和顺序调整，并在当前结果上看到更新。

## V0 明确不包含

- PDF 导出、图片导出、地图导出兼容性最终方案
- 持久化保存、账号体系、历史行程存档
- 多城市复杂规划
- 跨天重排、自动重规划、复杂协同编辑

## 上位企划

- [智能旅行助手.md](./../智能旅行助手.md) 是本项目的上位企划来源。
- V0 只截取其中的最小闭环；V1 及后续阶段应继续以这份企划为目标来源，而不是只围绕 V0 本身扩写。
- 如果 V1 需要决定“下一步实现什么”，应优先回到 `智能旅行助手.md` 中尚未纳入 V0 的能力，例如导出、更完整的编辑能力和更完整的应用体验。

## 对 V1 的约束

- V1 应建立在 V0 已稳定的请求、结果和交互边界之上扩展，而不是回头重定义 V0。
- 如果一个能力不属于上面的“必须包含”，默认它不属于 V0，应放到 V1 及之后阶段讨论。
- 如果 V1 要扩展导出、持久化、复杂编辑或更强规划能力，应在不破坏 V0 最小闭环的前提下追加设计。
